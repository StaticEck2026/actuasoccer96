# Actua Soccer / Euro 96 — Godot 4 port

A line-by-line port of the 1996 Gremlin Interactive match engine (Actua Soccer,
Euro 96 build) from the original Watcom C/C++ source in `../SOURCE` to Godot 4.3
GDScript. It is a port, not an emulation: every gameplay routine of the original
(`FOOTBALL.CPP`, `ACTIONS.CPP`, `INTELL.CPP`, `BALL.CPP`, `BALLINT.CPP`,
`RULES.CPP`, `USER.CPP`, `3D_UPD2.CPP`, `MATHS.CPP`, the local-input half of
`NETWORK.C`, the keyboard handler `KEYH.CPP`, and the in-match parts of `3DENG.C`)
has a GDScript counterpart with the same function names, structure, constants and
quirks. Networking (NetNow/modem/serial play and the network state-sync code) is
deliberately not ported.

## Running

* Open `godot/` in Godot 4.3 and press Play, or
  `godot --path godot` (selection screen), or `godot --path godot -- --quick`
  (straight into England v Germany with keyboard 1 on the home team).
* Controls (original defaults, `USER.CPP init_keyboard`):
  * Keyboard 1: arrow keys, fire 1 = keypad 0, fire 2 = keypad `.`
  * Keyboard 2: A / Z / `,` / `.` to move, fire 1 = Q, fire 2 = `/`
  * Joypads 1/2: left stick or d-pad, A = fire 1, B/X = fire 2
  * F1–F4: in-game options menu for user 1–4 (formation, substitutions, replay, stats)
  * 1–8: camera (auto, plan, half-plan, manual, player, wire, referee, isometric);
    keypad 4/6 camera distance, keypad 8/2 height, keypad 5 reset
  * F9: manual/automatic player switching, Pause: pause, Esc: quit match (Y/N)

## Layout

```
scripts/core/cbase.gd      C runtime helpers (unsigned char/short wrap, integer abs(), Watcom rand(), macros)
scripts/core/consts.gd     every #define of the game  (generated by tools/gen_consts.py)
scripts/core/glob.gd       every global + struct      (generated by tools/gen_glob.py)
scripts/game/*.gd          the ported modules (assembled from scripts/game/parts by tools/assemble.py)
scripts/game/eng3d.gd      3DENG.C menu/vidi/state functions called by the logic
scripts/render/            Godot replacement for the 3DENG.C software renderer + 2D overlays
scripts/frontend/          pre-match setup (FOOT.CPP main / EURO_MAT.CPP hand-over) and selection screen
scripts/main.gd            driver: 200 Hz timer interrupt, keyboard interrupt, joystick port, frame loop
assets/, data/             converted original data (tools/extract_assets.py, tools/extract_squads.py, TAC_*.TAC)
tests/                     headless simulations and compile checks
docs/PORTING.md            porting conventions;  docs/ASSETS.md  data formats;  docs/FUNCTION_INDEX.md
```

## How the missing pieces were recovered

The source release lacks the game's own headers (`global.h`, the game `defines.h`,
`glob_var.h`, `ball.dta`) and the render-data index (`actrend.equ`). They were
recovered from the original compiled objects in `SOURCE/*.OBJ`, which were built
unoptimised with full Watcom debug information:

* `tools/omf.py` parses the OMF objects; `tools/annotate.py` produces disassembly
  listings interleaved with the matching source lines (via the LINNUM records);
  every `#define` value (~400) was read back from the instructions that use it
  (`tools/recovered/*.json` holds value + evidence for each).
* `tools/wdbg.py` decodes the Watcom `$$TYPES/$$SYMBOLS` debug info: exact types of
  all ~630 globals and the layout of every struct (`match_player` etc.); initial
  values come from the `_DATA` segments and the C++ dynamic initialisers.
* Details that matter for fidelity and were verified in the object code: Watcom
  `char` is unsigned; `abs()` on floats truncates to int; `rand()` is Watcom's LCG
  (×1103515245+12345, bits 16–30); `PI` is 3.1415926536; `match_mode` and the
  action ids have range semantics.

## Known differences / not ported

* Network play (by request) and the network state checksum/resync.
* Audio: the sample banks (crowd, commentary, effects) are not in the source
  release. All audio calls are kept and routed to `Audio` (`scripts/game/audio.gd`),
  which can forward them to a sound layer via `Audio.sink`.
* The source text is an older revision than the shipped objects in a few places
  (e.g. player stats in `init_player_stats` read `game_data[]`; the front-end glue
  fills `game_data[]` for all 16 Euro teams so the source logic runs as written).
* The Euro 96 front end (tournament, squad management, redefine keys) is replaced
  by a single selection screen; the values it passes to the match are the same.
* Renderer (`scripts/render/`): the 3DENG.C painter's-algorithm renderer is
  reproduced (same draw order, camera/projection maths, sprite-built players from
  the 28 motion-capture points, palette/transparency rules, ground and sky
  routine, LODs, highlights, shadows, vidi wall) on the GPU. Deviations: world
  polygons are perspective-correct (the original was affine), the translucent
  shadow/grey filters are 50% blends instead of nearest-palette lookup tables,
  speech-bubble sprites and the FAP video-wall clips are not drawn.
* The kit artwork comes from the shipped EUROREND.DAT, whose team table still
  points at the Actua Soccer (World Cup) kits — e.g. England play in red. This is
  what the data contains; it is reproduced as is.
* The match runs in the compiled default 640x400 mode (F10 toggles 320x200, `-`/`=`
  screen size, F5–F8 detail levels), shown in the largest 4:3 area of the window.
